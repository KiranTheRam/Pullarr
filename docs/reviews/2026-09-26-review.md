# Pullarr backend and user experience review

Reviewed 2026-09-26, branch `chore/dependency-maintenance-2026-09`, commit `4b5e496`. The checkout was clean at the start. This report is the only repository change; no fixes, commits, pushes, deployments, or production operations were performed.

The highest priorities are closing the unauthenticated file-read vulnerability, rejecting invalid archives, and recovering interrupted downloads. The existing tests pass, but do not cover the reproduced failures below.

## Confirmed findings, in priority order

### 1. High — unauthenticated requests can read outside the frontend directory

**Location:** `backend/pullarr/main.py:61–65`.

The SPA fallback joins the URL path to `STATIC_DIR` and returns any existing file without resolving and checking containment. Encoded traversal escapes the static directory. This route sits outside API-key protection.

**Evidence:** A local ASGI request to `/..%2Fpyproject.toml`, without authentication, returned HTTP 200 and the exact backend package manifest. The same harmless request succeeded against Suika's running candidate. No secrets or production files were requested. The relevant deployed source matches the checkout.

**Impact:** A caller who can reach this endpoint can retrieve files readable by the application process outside the intended public directory. External reverse-proxy protections were not assessed, and the production instance was not tested.

**Fix:** Resolve requested paths, enforce containment within the resolved static root (including symlinks), reject escapes, and use safe static-file serving. Add regression cases for encoded traversal and symlinks.

### 2. High — invalid comic files can be marked successfully downloaded

**Location:** `backend/pullarr/library/importer.py:63–74`; completion marking in `backend/pullarr/jobs/tasks.py`.

`validate_archive()` only validates files for which `zipfile.is_zipfile()` returns true. A nonempty invalid ZIP, HTML error response, or arbitrary bytes bypass those checks entirely.

**Evidence:** In a temporary directory, importing an HTML error page named `Test 001.cbz` succeeded; the normal completion helper marked its issue downloaded. No actual comic was fetched.

**Impact:** Unreadable files enter the library and stop automatic searches for the missing issue. Invalid successful HTTP responses also do not trigger mirror fallback, because validation happens after a mirror is selected.

**Fix:** Validate the intended container format before accepting an import, with an explicit policy for CBR/CB7. Treat invalid mirror payloads as mirror failures, try remaining mirrors, and only mark ownership after validation succeeds.

### 3. High — a restart strands active direct downloads

**Location:** `backend/pullarr/jobs/scheduler.py:16–19`, `backend/pullarr/jobs/service.py:recover_interrupted_jobs`, `backend/pullarr/jobs/tasks.py:618–630`.

Startup recovery handles `Job` records only. Direct-download processing selects only `queued` rows. A download left `downloading` or `importing` by termination therefore never resumes, fails, or becomes eligible for the normal Retry action. It also continues to reserve its issue against automatic grabs.

**Evidence:** With an in-memory database, a persisted direct download in `downloading` stayed in that state after startup recovery; a queue pass invoked the worker zero times.

**Fix:** Reconcile interrupted downloads at startup. Requeue safe transfers, handle already-imported files idempotently, and expose an interrupted state where manual action is necessary. Include partial-file cleanup and a restart regression test.

### 4. Medium — retrying a removed queued download cancels the retry

**Location:** `backend/pullarr/api/queue.py:142–145` and `retry_download()`; cancellation state in `backend/pullarr/jobs/tasks.py`.

Removal sets an in-memory cancellation flag even for a queued download that has no active worker. Retry resets the database fields but leaves the flag intact. Only the worker's eventual cleanup clears it.

**Evidence:** Calling remove, then retry, on a queued direct download in an isolated database produced `status=queued` and `cancelled=True`; the downloader's cancellation check raised `DownloadCancelled`.

**Impact:** The first retry fails until the stale flag is consumed or the process restarts. The user sees a download they explicitly retried cancelled again.

**Fix:** Scope cancellation to a specific active attempt, and clear stale cancellation state when starting a new attempt. Cover removal before start and retry during cancellation separately.

### 5. Medium — blocking one release also blocks good alternatives

**Location:** `backend/pullarr/jobs/tasks.py:905–922`, `_grab_matches()`.

The monitor creates both a release-level block and an `(issue_id, source_name)` block. A blocked release consequently excludes every release for that issue from the same source indefinitely. Recent failures impose the same broad exclusion for 24 hours.

**Evidence:** An isolated test with blocked URL A and a valid matching alternative URL B from GetComics queued zero downloads.

**Impact:** Clicking Block on a bad release can prevent automatic recovery via a good replacement, particularly because GetComics is the only configured DDL source implementation.

**Fix:** Block the release identity independently from short-lived source-health backoff. Make the UI distinguish “block this release” from “stop monitoring this issue.”

### 6. Medium — provider outages appear as an empty successful search

**Location:** `backend/pullarr/api/search.py:search_releases`; `frontend/src/pages/SeriesDetail.tsx:194`.

The search endpoint silently catches source exceptions and returns whatever releases remain, including an empty list. The UI then says “No releases found” and suggests checking source settings.

**Evidence:** An isolated source mock raising a proxy-unavailable error produced an ordinary empty search response.

**Impact:** A VPN proxy failure, provider timeout, or upstream rejection is indistinguishable from a genuine lack of releases. This makes diagnosis unnecessarily difficult.

**Fix:** Return per-source outcomes and partial-result warnings. If every enabled source fails, report that failure explicitly with a Retry action. Preserve the configured VPN route; do not retry via direct egress.

### 7. Medium — an empty History filter hides the controls needed to clear it

**Location:** `frontend/src/pages/Activity.tsx:139–145`.

History returns its empty state before rendering the filter toolbar.

**Evidence:** In Suika, History initially showed existing entries and filter buttons. Selecting `failed` returned no matches and removed every filter button, including `all`. Switching tabs and returning is a workaround because the component remounts.

**Fix:** Keep filters visible in loading, error, and empty states; say “No events match this filter” and provide Clear filter. Reserve “No history yet” for an actually empty history.

### 8. Medium — the supplied Compose file launches the wrong application image

**Location:** `docker-compose.yml:3`.

The `pullarr` service points at `kirantheram/mangarr:latest`, while exposing Pullarr's port and configuration mounts.

**Evidence:** Direct inspection of the tracked Compose file. Suika uses its separate maintenance Compose configuration and is running `arr-maintenance/pullarr:candidate`, so this finding does not describe its current deployment.

**Fix:** Use the intended Pullarr image and verify a fresh Compose startup. Keep deployment examples consistent with the actual release registry and image convention.

## Additional backend improvements

- **Keep archive and filesystem work off the request event loop.** Async routes and scheduled tasks call synchronous scanning, copying, hashing, ZIP validation, and metadata rewriting directly. Large packs or slow storage can stall API responses, progress updates, and cancellation. Run bounded blocking work in an appropriate worker, keeping database sessions within their supported execution context. No latency benchmark was performed in this review.
- **Make download completion and manual repair a coherent workflow.** `needs_attention` items appear in Queue, but its only row action is Remove. Manual file mapping updates issues without completing the associated download record. Add a direct link to the affected series/files, a mapping action, and a way to resolve the item without misclassifying it as failed or downloading it again.
- **Make builds reproducible.** Python dependencies use broad ranges without a committed lockfile. Docker runs a fresh dependency resolution on each build. Agree on a Python lock strategy and pin deployment image identities. The frontend already uses `npm ci` in Docker. There is no root `.dockerignore`; add exclusions for local environments, data, and build output.
- **Make the authentication boundary explicit.** `/initialize.json` intentionally gives any reachable caller the UI API key; API keys alone are therefore not a login boundary. Document the required trusted-network/reverse-proxy boundary, or add real authenticated UI sessions if remote access is intended. This is separate from the file-read defect above. Production perimeter configuration was not inspected.

## Additional user experience improvements

- **Make every mutation failure visible.** Queue removal has mutation error state but does not render it. Series deletion likewise lacks the error display supplied for neighboring actions. Show an actionable message beside the operation and preserve selection for retry.
- **Show retry timing and attempt state.** The backend already provides `next_retry_at` and attempt counts. A queue row should say “Retrying in 2 minutes — attempt 2 of 5” rather than only `queued` and a percentage.
- **Add history and failure pagination.** History defaults to 100 rows and supports an offset, but the UI offers no Load more control. Failed downloads also default to 100 without a UI paging mechanism. Older unresolved problems become inaccessible through these views.
- **Protect unsaved settings on in-app navigation.** The current `beforeunload` handler covers browser departure, but sidebar routing does not trigger it. Add route-change handling or preserve the draft, with a clear unsaved indicator.
- **Finish keyboard and screen-reader support.** The shared modal initially focuses Close but lacks focus trapping and focus restoration. Toggle controls have a switch role without their own accessible name; associate each with its visible setting label. Several queue checkboxes are also unlabeled.
